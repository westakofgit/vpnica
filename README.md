# vpnica

`vpnica` автоматически разворачивает на личном VPS:

- OpenVPN по UDP/443;
- Telemt Fake TLS по TCP/443 — прокси только для Telegram;
- полный и два выборочных режима маршрутизации;
- ночное обновление списков маршрутов;
- firewall с разрешением только SSH, OpenVPN и Telemt;
- перенос настроек на другой сервер через зашифрованную резервную копию;
- временную ссылку для скачивания готового комплекта через браузер.

TCP и UDP могут использовать один номер порта без конфликта.

## Быстрая установка

Нужен чистый VPS с Ubuntu или Debian и доступом `root`.

1. Подключитесь к серверу по SSH:

   ```bash
   ssh root@IP_СЕРВЕРА
   ```

2. Запустите установку:

   ```bash
   curl -fsSL https://raw.githubusercontent.com/westakofgit/vpnica/main/bootstrap.sh | bash -s -- --host auto
   ```

3. Не закрывайте SSH и дождитесь сообщения `vpnica установлена`.

`auto` сам определяет публичный IPv4 сервера. Если домен уже направлен на VPS, его можно указать сразу:

```bash
curl -fsSL https://raw.githubusercontent.com/westakofgit/vpnica/main/bootstrap.sh | bash -s -- --host node.example.com
```

Установщик поставит необходимые пакеты, запустит OpenVPN и Telemt, создаст клиентские профили и выведет примерно такой результат:

```text
vpnica установлена.
Адрес подключения: 203.0.113.10

Скачать готовый комплект в браузере:
http://203.0.113.10/d/длинный-случайный-токен/vpnica-203.0.113.10.zip

Скачать файлы через терминал на своём компьютере:
mkdir -p ./vpnica-outputs/203.0.113.10 && scp -r root@203.0.113.10:/opt/vpnica/outputs/203.0.113.10/. ./vpnica-outputs/203.0.113.10/

Ссылка работает 30 минут и допускает до 3 успешных скачиваний.
```

Выберите удобный вариант: скопируйте ссылку из SSH в браузер и скачайте ZIP либо выполните показанную команду `scp` в отдельном терминале на своём компьютере. Локальный firewall сам временно откроет TCP-порт из ссылки и закроет его после истечения ссылки. Если у провайдера VPS включён отдельный внешний сетевой экран, разрешите в нём этот порт вручную. Обычно используется порт 80; если он уже занят, установщик выберет свободный высокий порт.

Ссылка использует обычный HTTP. Адрес защищён длинным случайным токеном и действует ограниченное время, но содержимое при передаче не шифруется. Не пересылайте ссылку посторонним и не скачивайте комплект через недоверенную публичную сеть.

## Что находится в архиве

Сначала распакуйте ZIP и откройте `START-HERE.html`. Внутри будут понятные кнопки, описание профилей и ссылка Telegram.

| Файл | Назначение |
| --- | --- |
| `family.ovpn` | Весь IPv4-трафик через VPN |
| `family-split-exact.ovpn` | Через VPN только адреса из обновляемого списка и ручные добавления |
| `family-russia-direct.ovpn` | Российские IPv4-сети напрямую, остальной IPv4-трафик через VPN |
| `telemt-https-link.txt` | Кликабельная ссылка подключения Telegram |
| `telemt-link.txt` | Ссылка Telegram в формате `tg://` |
| `telemt-qr.png` | QR-код подключения Telemt |
| `README.txt` | Краткая текстовая инструкция |

Файл `.ovpn` импортируется в OpenVPN Connect или в настройки OpenVPN на роутере. Для полного VPN используйте `family.ovpn`.

Один профиль `family.ovpn` можно установить на несколько своих устройств: сервер допускает одновременные подключения с этим профилем.

## Если ссылка истекла

Войдите на сервер по SSH и выполните:

```bash
vpnica share
```

Команда заново сформирует профили, соберёт архив и выдаст новую временную ссылку. Предыдущая ссылка перестанет работать.

Готовые файлы также всегда остаются на сервере в каталоге:

```text
/opt/vpnica/outputs/<адрес-сервера>/
```

Их можно забрать по SSH без временной HTTP-ссылки:

```bash
mkdir -p ./vpnica-outputs/IP_СЕРВЕРА && scp -r root@IP_СЕРВЕРА:/opt/vpnica/outputs/IP_СЕРВЕРА/. ./vpnica-outputs/IP_СЕРВЕРА/
```

Эту команду нужно выполнять на своём компьютере, а не внутри SSH-сессии сервера.

## Полезные команды

```bash
vpnica status
```

Показать состояние OpenVPN и Telemt.

```bash
vpnica firewall status
```

Показать состояние firewall. Команда `vpnica firewall apply` повторно применяет безопасные правила.

```bash
vpnica share
```

Создать новую временную ссылку на комплект.

```bash
vpnica export
```

Заново сформировать профили, ссылки и QR без запуска временного веб-сервера.

```bash
vpnica host set node.example.com
```

Переключить клиентские файлы с IP на домен без перевыпуска ключей.

```bash
vpnica routes update
```

Вручную обновить списки маршрутов.

```bash
vpnica routes add example.com
vpnica routes add '*.example.com'
vpnica routes add 203.0.113.10
vpnica routes add 203.0.113.0/24
```

Добавить собственный домен, известные публичные поддомены, IPv4 или CIDR в split-маршруты. Маску `*.example.com` обязательно заключайте в кавычки.

```bash
vpnica backup
```

Создать зашифрованную резервную копию для переноса на другой VPS. Пароль шифрования нигде не сохраняется.

## Обновление маршрутов

Установщик включает автоматическое обновление списков каждую ночь в 04:15 по Москве. Ручные домены и адреса хранятся отдельно в `config/routes/` и при обновлении не удаляются.

`family-split-exact.ovpn` содержит точные сети OpenCCK без расширения диапазонов. `family-russia-direct.ovpn` использует `net_gateway`, поэтому клиент должен поддерживать исключающие маршруты. Маршруты устанавливаются на клиентском устройстве только на время VPN-подключения.

Для маски `*.example.com` список публично известных поддоменов собирается из Certificate Transparency и обновляется вместе с остальными маршрутами. Закрытые и нигде не опубликованные имена автоматически найти невозможно.

## Домен и переезд на другой сервер

Система работает как по IP, так и по домену. Для первого запуска домен не обязателен.

Если позже домен будет направлен на сервер, выполните:

```bash
vpnica host set node.example.com
vpnica share
```

После переезда достаточно поменять DNS-запись домена и восстановить зашифрованную резервную копию. Подробности находятся в [`docs/MIGRATION.md`](docs/MIGRATION.md).

## Для разработчиков

Проект устанавливается в `/opt/vpnica`. Состояние контейнеров и ключи находятся только в `state/`; клиентские файлы — в `outputs/`. Контейнеры можно пересоздавать без потери ключей. Новый транспорт добавляется отдельным Compose-сервисом и отдельной папкой состояния. Рекомендации находятся в [`docs/ADD_PROTOCOL.md`](docs/ADD_PROTOCOL.md).

Если проект уже скачан локально, установка запускается так:

```bash
sudo ./install.sh --host auto
```

## Безопасность

- Установщик разрешает входящие TCP-порты SSH, TCP/443 для Telemt и UDP/443 для OpenVPN; остальные входящие соединения блокируются.
- Порт временного HTTP-скачивания открывается только на срок действия ссылки и затем закрывается автоматически.
- Исходящие соединения не блокируются: они нужны для DNS, обновлений, Docker и списков маршрутов.
- Docker-порты дополнительно фильтруются через отдельную цепочку `VPNICA-DOCKER`, потому что опубликованные контейнерные порты могут обходить обычные правила UFW.
- `outputs/` содержит действующие клиентские ключи — не публикуйте эту папку.
- Временная HTTP-ссылка предназначена для осознанного кратковременного использования и не заменяет HTTPS или SCP.
- Не добавляйте `.env`, `state/`, `outputs/`, `backups/` и `config/servers/` в Git.
- Храните зашифрованную резервную копию вне VPS.
- После установки замените первоначальный пароль `root` и настройте вход по SSH-ключу.
- Образы контейнеров закреплены по digest; обновляйте их намеренно.
