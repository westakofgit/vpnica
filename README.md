# vpnica

Переносимый модульный шлюз для личного VPS. Базовая конфигурация запускает два независимых транспорта на одном IPv4:

- OpenVPN по UDP/443 — универсальный VPN;
- Telemt Fake TLS по TCP/443 — отдельный прокси только для Telegram.

TCP и UDP используют один номер порта без конфликта. Обновляемые списки используются отдельным split-профилем; Smart DNS без собственного домена в эту конфигурацию не входит.

## Принципы

- состояние и ключи находятся только в `state/`;
- контейнеры можно пересоздавать без потери ключей;
- клиенты подключаются к `VPNICA_PUBLIC_HOST`, поэтому после появления домена IP можно заменить доменным именем;
- новый протокол добавляется отдельным Compose-файлом и отдельной папкой состояния;
- секреты и клиентские профили исключены из Git.

## Первый запуск

На чистом Ubuntu/Debian войти по SSH как root и выполнить:

`curl -fsSL https://raw.githubusercontent.com/westakofgit/vpnica/main/bootstrap.sh | bash -s -- --host auto`

Команда скачивает проект, определяет публичный IPv4 и устанавливает систему в `/opt/vpnica`.

Если проект уже распакован локально, можно запустить:

`sudo ./install.sh --host auto`

`auto` определяет публичный IPv4 сервера. Домен можно указать сразу:

`sudo ./install.sh --host node.example.com`

Установщик не перезаписывает существующие ключи. Он создаёт профили `family`, `family-split-exact`, `family-russia-direct`, ссылку и QR-код Telemt в `outputs/<адрес>/`, включает ночное обновление маршрутов и устанавливает команду `vpnica`.

После привязки домена заменить адрес без перегенерации ключей:

`sudo vpnica host set node.example.com`

Полезные команды:

- `sudo vpnica export` — заново сформировать профили, ссылку и QR;
- `sudo vpnica backup` — создать зашифрованную резервную копию;
- `sudo vpnica routes update` — вручную обновить маршруты;
- `sudo vpnica routes add example.com` — добавить домен, IPv4 или CIDR;
- `sudo vpnica status` — показать состояние контейнеров.

## Выборочная маршрутизация

Доступны три независимых режима:

- `family.ovpn` — весь IPv4-трафик через VPN;
- `family-split-exact.ovpn` — точные сети OpenCCK и ручные записи без расширения диапазонов;
- `family-russia-direct.ovpn` — весь IPv4-трафик через VPN, российские IPv4-сети из Russia OpenCCK идут напрямую через исходный шлюз.

Точные профили передают клиенту значительно больше маршрутов. `family-russia-direct.ovpn` использует `net_gateway`, поэтому требует клиент с поддержкой исключающих маршрутов. Исходные списки хранятся и обновляются на сервере, а готовые маршруты устанавливаются на клиенте на время VPN-подключения.

- Добавить домен, IPv4 или CIDR и сразу применить: `scripts/route-add.sh example.com`
- Добавить корневой домен и публично известные поддомены: `scripts/route-add.sh '*.example.com'`. Маску обязательно заключать в кавычки. Список поддоменов берётся из Certificate Transparency, кэшируется и обновляется вместе с остальными маршрутами; закрытые и нигде не опубликованные имена найти таким способом нельзя.
- Обновить списки вручную: `scripts/routes-update.sh`
- Включить ночное обновление в 04:15 по Москве: `scripts/install-route-timer.sh`

Ручные записи хранятся в `config/routes/` и входят в зашифрованную резервную копию.

Настройки отдельных VPS хранятся в `config/servers/`.

## Резервная копия

`scripts/backup.sh` создаёт зашифрованный архив в `backups/`. Пароль шифрования нигде не сохраняется. Архив нужно хранить вне VPS.

Восстановление выполняется в новую пустую папку:

`scripts/restore.sh backups/<имя>.tar.gz.enc /opt/vpnica-restored`

Подробный порядок переезда описан в `docs/MIGRATION.md`.

## Безопасность

- Не добавляйте `.env`, `state/`, `outputs/` и резервные копии в Git.
- Файлы в `outputs/` содержат действующие ключи и ссылки доступа; не публикуйте и не открывайте общий доступ к этой папке в облачной синхронизации.
- Не храните незашифрованные резервные копии в облачной синхронизации.
- После первичной настройки замените первоначальный root-пароль сервера и используйте SSH-ключ.
- Образы закреплены по digest; обновляйте digest намеренно и только после проверки новой версии.
